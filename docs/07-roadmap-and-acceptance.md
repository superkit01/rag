## 2. 验收指标

首版验收目标沿用最初规划：

- 离线 gold set `Recall@10 >= 0.80`
- 引用精度 `>= 0.90`
- groundedness `>= 0.85`
- 问答 `p95 <= 10s`
- 单批 1,000 份文档导入成功率 `>= 99%`

## 6. 后续重点优化方向

以下方向作为 Phase 2/3 之后继续演进的重点，不要求在当前 MVP 内一次完成。

### 6.1 工程结构模块化

目标是把当前已经跑通的 MVP 结构继续拆成更清晰的边界：

- 导入、解析、预处理、切片、索引、检索、问答、评测各自形成独立模块。
- 模型 provider、检索后端、对象存储、工作流后端通过接口/工厂隔离。
- 将策略类配置从散落的环境变量逐步收敛为更可组合的配置对象。
- 为后续 connector、tools、agent、结构化数据导入预留稳定扩展点。

### 6.2 问答能力增强：tools、MCP 与 agent 接入

当前问答主要是“检索证据 + 生成回答”。后续可增强为更完整的 agentic RAG：

- 让 LLM 可调用 tools，例如文档检索、结构化查询、图表生成、代码执行、外部系统查询。
- 接入 MCP，把企业内部工具、数据库、文件系统、协作平台连接器作为标准 tool 暴露。
- 增加 agent 编排层，支持多步问题拆解、证据追踪、工具调用计划、失败重试和可观测 trace。
- 保持 grounded 约束：工具返回结果必须进入 evidence snapshot，最终回答仍要能回溯依据。

### 6.3 文档解析后的预处理模块

在 parser 和 chunker 之间增加独立的 document preprocessing 层：

- 文档结构化：识别标题层级、章节、表格、列表、页眉页脚、脚注、目录等结构。
- 噪音清洗：去除重复页眉页脚、页码、水印、目录残留、乱码、空白段、模板化声明。
- 内容规范化：统一标点、空白、编号、跨页断句、表格转 Markdown/JSON。
- 元数据增强：保留页码、段落位置、表格坐标、图片引用、章节路径、来源文件属性。
- 质量检测：记录解析置信度、异常段落、低质量 OCR、空文档、重复文档等诊断信息。

### 6.4 结构化数据导入与结构化 RAG

当前导入重点是 Word、PPT、PDF、Markdown、Text 等文本型文档。后续需要支持 Excel、CSV 等结构化数据：

- 增加 Excel、CSV、TSV 等结构化文件解析器。
- 将结构化数据导入到灵活且可查询的结构化存储中，例如 PostgreSQL 动态表、JSONB、DuckDB、ClickHouse 或专用 analytical store。
- 建立表级、列级、单元格级元数据，包括字段类型、表头、单位、枚举值、统计摘要、主键候选、时间列识别。
- 问答时根据问题自动选择文本检索、表格检索、SQL/DSL 查询或混合路径。
- 参考市场上的 structured-data RAG 实现：text-to-SQL、table QA、schema linking、数据摘要索引、表格行列混合召回、查询结果再生成。
- 回答需要能引用结构化来源，例如工作表、表名、行号、列名、筛选条件和 SQL/DSL 查询。

### 6.5 多模态与富内容回答

当前回答主要是文本和引用。后续需要支持图片、代码、图表等富内容输出：

- 图片回答：可由模型直接生成、由工具生成，或从文档原图/截图中检索并引用。
- 代码回答：支持代码块、可执行片段、Notebook/脚本生成，以及运行结果回传。
- 图表回答：对结构化数据查询结果生成表格、折线图、柱状图、饼图等可视化。
- 文件型回答：生成报告、PPT、Excel、图片等 artifact，并在前端可预览/下载。
- 实现方式需要调研主流方案：
  - tool calling：模型决定何时调用绘图、代码执行、图片检索、文件生成工具。
  - agent workflow：多步规划、执行、校验，再汇总成最终回答。
  - multimodal response schema：后端返回结构化 blocks，由前端按文本、图片、代码、表格、图表分别渲染。
- 所有非文本输出也应保留 evidence/source trace，避免生成结果无法审计。
